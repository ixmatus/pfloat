# ADR-0026: Riemann zeta function on the real line

- **Status**: accepted
- **Date**: 2026-05-17

## Context

Roadmap slice 6r closes the last Phase 6 surface: the Riemann zeta
function for real argument. With it the tier-2 specials roadmap
(Bessel `J`/`Y`/`I`/`K`, `Ei`/`Si`/`Ci`/`li`, Airy, AGM, zeta) is
complete. zeta has no order parameter and no recurrence machinery,
so it does not reuse the Bessel kernels; its structural relatives
are the constant-composing specials.

Two planning forks were resolved by verification rather than
recall, and both contradicted the resume sketch:

**Oracle.** rug 1.30 / MPFR was checked directly (`gmp-mpfr-sys`
`src/mpfr.rs` declares `mpfr_zeta` / `mpfr_zeta_ui`; rug
`src/float/big.rs` exposes `Float::zeta` / `zeta_round` /
`zeta_ref`). zeta therefore has a native bit-exact MPFR oracle, so
the differential lane is the `differential_jn` / `differential_yn`
posture (bit-exact `assert_eq!` under NearestEven across the full
`TRANSCENDENTAL_PRECISIONS` including `p = 1024`), not 6q's
no-primitive tiered oracle.

**Algorithm.** The roadmap and DESIGN.md specified Euler–Maclaurin
reusing the 17-pair Bernoulli table in `gamma_stirling`. Deriving
the truncation bound showed that to be insufficient for the
bit-exact `p = 1024` lane: since `|B_{2k}/(2k)!| ≈ 2/(2π)^{2k}`,
the first omitted correction at `k = 18` is `≈ 2^{-94}` times a
`(s)_{35}·N^{1−s−36}` factor, so a 17-term correction caps the
accuracy near 90 bits no matter how long the leading sum, and
reaching 1024 bits would need `N ≳ 5·10^8` sum terms. The
recalled-assumption failure mode (the 6n Airy / 6q `K`-sign
precedent, [`feedback_derive_dont_recall_coefficients`]) recurred
at the planning level and was caught by deriving the bound instead
of trusting the roadmap text. The algorithm was changed to the
Borwein / Cohen–Villegas–Zagier alternating-series acceleration.

All formulas were derived from primary sources (user-authorized
`WebFetch` of DLMF §25.2, §25.4, §25.6, §25.11, §24.2, §24.4 and
the Cohen–Villegas–Zagier paper, *Experiment. Math.* 9 (2000),
read from the saved PDF), not recalled.

## Decision

**Positive axis, `s > 0`, `s ≠ 1`: Borwein / CVZ acceleration of
the Dirichlet eta series.** DLMF 25.2.3
`ζ(s) = (1−2^{1−s})⁻¹ Σ_{k≥0} (−1)^k/(k+1)^s` holds for
`ℜ s > 0`, and `a_k = 1/(k+1)^s = Γ(s)⁻¹∫₀¹ xᵏ(−ln x)^{s−1}dx` is
the moment sequence of a positive measure for every `s > 0`, so
the CVZ Proposition 1 hypothesis (and its
`relative error ≤ 2·(3+√8)^{−n}` bound) holds on the whole open
right half-line, including the critical strip `0 < s < 1` where
the Dirichlet series itself diverges. CVZ Algorithm 1 was
**derived from the CVZ primary source and verified by reproducing
the paper's own worked `n = 1, 2` weighted sums** (`2a₀/3`,
`(16a₀−8a₁)/17`) before shipping, the derive-don't-recall reflex;
the sign of the `c = b − c` step and the `b` recurrence were
pinned this way:

```text
d = (3+√8)^n;  d = (d + 1/d)/2;     // = d_n = ½((3+√8)^n+(3−√8)^n)
b = −1;  c = −d;  s = 0;
for k = 0 .. n−1:
    c = b − c
    s = s + c · a_k                  // a_k = (k+1)^{−s}
    b = (k+n)(k−n)·b / ((k+½)(k+1))
return s / d;
```

then `ζ(s) = (s/d_n) / (1−2^{1−s})`. `n ≈ p·ln2/ln(3+√8) ≈
0.3933 p` terms give `p` bits. The intermediate `s` reaches
magnitude `≈ d_n·ζ(s)` and `d_n ≈ 2^{2.543 n} ≈ 2^p`, so
recovering `p` bits after the `/d_n` needs a working precision
`≈ 2p` (derived from the cancellation structure, the
`gamma_stirling` boost analog), plus `−log₂|s−1|` extra bits to
absorb the `(1−2^{1−s})⁻¹` blow-up near the pole.

**Negative axis, `s < 0`: functional equation DLMF 25.4.2.**
`ζ(s) = 2·(2π)^{s−1}·sin(πs/2)·Γ(1−s)·ζ(1−s)`, quoted verbatim
from the DLMF primary source. The companion 25.4.1
`ζ(1−s) = 2·(2π)^{−s}·cos(πs/2)·Γ(s)·ζ(s)` is the **wrong branch**
for the negative axis; the sin-vs-cos and Γ(1−s)-vs-Γ(s) choice is
the derive-don't-recall catch at the convention level (the
ADR-0025 `K`-recurrence-sign precedent). It was pinned numerically
by `ζ(−1) = 2·(2π)⁻²·(−1)·1·(π²/6) = −1/12` before shipping. For
`s < 0` the reflected argument `1−s > 1` lands strictly inside the
Borwein moment region, so `ζ(1−s)` is the well-conditioned Borwein
path; the factors multiply with no cancellation, so a single
`+96`-bit working boost over the `Γ`/`sin`/`pow` composition
suffices.

**Special values (DLMF 25.2 / 25.6, derived verbatim).**

| input | ζ result | status | source |
|-------|----------|--------|--------|
| `qNaN` | `qNaN` | `OK` | — |
| `sNaN` | `qNaN` | `INVALID` | — |
| `s = 1` | `+∞` (simple pole, residue +1; `+∞` the `s → 1⁺` side) | `DIV_BY_ZERO` | 25.2 |
| `s = 0` | `−1/2` exact | `OK` | 25.6.1 |
| `s = −2n` (`n ≥ 1`) | `+0` exact (trivial zero) | `OK` | 25.6.4 |
| `s = +∞` | `1` (genuine Dirichlet limit) | `OK` | 25.2.1 |
| `s = −∞` | `qNaN` | `INVALID` | derived from 25.4.2 |
| finite `s > 0`, `s ≠ 1` | Borwein/CVZ | `OK` | 25.2.3 |
| finite `s < 0` | functional equation | `OK` | 25.4.2 |

`ζ(1)` raising `DIV_BY_ZERO` with `+∞` follows the pole convention
of `Ci(0)` / `li(1)` / `K_n(0⁺)` (ADR-0019/0025). The trivial
zeros are special-cased to exact `+0` so the functional equation's
`sin(πs/2) = 0` cancellation never has to synthesize an exact
zero. **`ζ(−∞) = qNaN + INVALID` is a derived convention, not the
decaying-envelope choice.** Via the functional equation `Γ(1−s)`
grows super-exponentially while `sin(πs/2)` oscillates in
`[−1, 1]`, so `|ζ(s)|` diverges *and* does not converge: an
*unbounded* non-converging oscillation. The `J`/`Y`/Airy
`(±∞) → +0` convention covers a *bounded* non-converging
oscillation, where `+0` is a total-keeping choice; with no limit
and no finite total-keeping value here, the honest convention is
`qNaN + INVALID`. This is the K-vs-Y `+∞`/`+0` distinction of
ADR-0025 applied one rung further.

**Feature.** A new `zeta = ["specials"]` cluster feature
(roadmap open-decision #2, user-confirmed), matching the
`bessel`/`integrals`/`airy` precedent; zeta is a distinct family
and embedded users compile it out independently.

**Differential lane.** Bit-exact vs MPFR `Float::zeta_ref()` under
NearestEven across the full `TRANSCENDENTAL_PRECISIONS` including
`p = 1024` (user-confirmed). No custom `zeta_ref` helper is needed
(rug provides it). NearestEven-only, no Ziv (the 6o/6p/6q
posture).

## Consequences

- The real-line zeta surface is complete for v1.0 and Phase 6 is
  closed. Complex-axis zeta and Riemann–Siegel remain out of scope
  (DESIGN.md, roadmap).
- The Euler–Maclaurin → Borwein deviation from the roadmap is
  recorded here, in the `zeta.rs` module doc, and in the corrected
  DESIGN.md and roadmap text (the honest-deviation posture: promote
  the rationale in tree, not a silent substitution). The
  derived ≈ 90-bit Bernoulli ceiling is the load-bearing reason and
  is stated so the decision is not relitigated.
- No Bernoulli-number kernel is needed; the originally planned
  `gamma_stirling` `B_{2k}` accessor is not introduced (a frugality
  win, and it avoids dragging big-integer rational arithmetic into
  a float crate).
- The full bit-exact lane (including the `Γ`/`sin`/`pow`-composing
  negative axis at `p = 1024`) passed locally, positive evidence
  that the derived `≈ 2p` working precision yields the
  correctly-NearestEven-rounded result, not merely a close one. It
  remains a deliberately slow CI tier
  ([`feedback_differential_lane_cost`]).
- The NE-only tier is a documented limitation: `pow` is still the
  only transcendental with five-mode correct rounding. Extending
  the `pow_ziv` driver to zeta is a clean future slice.
