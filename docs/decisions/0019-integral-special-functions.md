# ADR-0019: Integral special functions (Ei, Si, Ci, li)

Status: accepted (slice 6m)

## Context

The roadmap's tier-2 surface includes the four classical integral
special functions: the exponential integral `Ei`, the sine and cosine
integrals `Si` and `Ci`, and the logarithmic integral `li`. Three of
the four need the Euler-Mascheroni constant γ, which slice 6m0 landed
as its own sub-slice (ADR-0018) so this slice could assume it.

Two design questions are specific to this cluster and are not
answerable from the existing kernels:

1. pfloat is real-only. `Ei`, `Ci`, and `li` have branch structure
   that takes them complex off part of the real line, so the real
   domain and the pole/flag behaviour have to be pinned.
2. MPFR (the differential oracle for every other transcendental)
   exposes only `mpfr_eint`. It has no `Si`, `Ci`, or `li`, and its
   `eint` returns NaN for negative argument. The standard bit-exact
   MPFR differential lane therefore cannot cover three of the four.

## Decision

1. **Reuse the `erf` two-regime kernel shape.** Each of
   `src/math/{ei,si,ci,li}.rs` dispatches on the binary exponent of
   the argument: a convergent power series for small argument
   (DLMF 6.6.2 for `Ei`, 6.6.5 for `Si`, 6.6.6 for `Ci`) and a
   divergent asymptotic series summed to its smallest term for large
   argument (DLMF 6.12). The threshold is the integer-arithmetic
   `asymptotic_threshold_exponent`, the working-precision boost is the
   `erf_maclaurin` guard idiom (extended to the alternating-series
   cancellation), and results flow through `round_to_precision` then
   `auto_raise`, returning `(value, Status)`. `Si` and `Ci` share the
   asymptotic auxiliaries `f` and `g` (DLMF 6.12.1-2) in `si.rs`.
   `li(x)` composes `ln` then the `Ei` kernel (`li(x) = Ei(ln x)`,
   DLMF 6.2.8). All series and asymptotic forms are derived from DLMF
   Chapter 6, cited in the module docs, not recalled from any
   implementation.

2. **Real-only domain and pole conventions.**

   | function | domain | poles / edges |
   | --- | --- | --- |
   | `Ei` | `x ≠ 0` | `Ei(±0) = −∞` + `DIV_BY_ZERO`; `Ei(+∞)=+∞`; `Ei(−∞)=−0` |
   | `Si` | all real (entire, odd) | `Si(±0)=±0`; `Si(±∞)=±π/2` |
   | `Ci` | `x > 0` | `Ci(+0) = −∞` + `DIV_BY_ZERO`; `Ci(+∞)=+0`; `x<0` ⇒ NaN + `INVALID` |
   | `li` | `x > 0` | `li(0)=0` (not a pole); `li(1) = −∞` + `DIV_BY_ZERO`; `li(+∞)=+∞`; `x<0` ⇒ NaN + `INVALID` |

   The pole flag is `DIV_BY_ZERO`, matching the `ln(±0)` convention
   already in the crate. `Ci(−x)` and `li(x<0)` are genuinely complex;
   returning `NaN` + `INVALID` is the real-only contract and
   supersedes the roadmap's loose "Ci is even" shorthand. `li(0)=0`
   is the defining integral over an empty interval and deliberately
   raises no flag even though `ln 0 = −∞`.

3. **Tiered differential oracle.** `Ei` differentials bit-exact
   against `mpfr_eint` for `x > 0`; its negative-`x` branch (a real
   value with no MPFR oracle) gets a high-precision self-consistency
   sweep. `li` differentials against `mpfr_eint(mpfr_log(x))` for
   `x > 1` (to a few ULP, since the composition double-rounds), with
   self-consistency on `(0,1)`. `Si` and `Ci`, which have no MPFR
   form at all, are pinned against a checked-in authoritative
   reference table generated by `sympy` / mpmath at 340 digits (the
   same primary-source recipe and "treated as a fact" provenance as
   the γ reference in ADR-0018), parsed by the bit-exact decimal
   parser, plus a self-consistency sweep. Kani edge harnesses and
   proptest identity/domain properties (`Si` odd, `Ei(x)=li(eˣ)`,
   `Ci` small-`x` envelope, the domain-flag rules) round out the
   scaffold.

4. **`integrals = ["specials"]` feature.** The cluster gates behind a
   new feature so embedded users opt in. `differential-mpfr` and the
   CI feature strings include it.

## Consequences

- The four functions reach any target precision (γ is uncapped per
  ADR-0018; the series/asymptotic dispatch has no precision ceiling),
  consistent with the no-cap principle restored in 7b2.
- `Si`/`Ci` correctness rests on the `sympy`/mpmath reference table at
  the tabulated points plus self-consistency between precisions, not
  on an independent same-precision oracle at every random input. This
  is weaker than the bit-exact MPFR lane the other transcendentals
  enjoy; it is the strongest check available given MPFR's surface, and
  it is the option recorded as chosen for this slice.
- `li` for `x > 1` is checked only to a few ULP because both pfloat
  and the MPFR composition double-round `eint(ln x)`. Tightening `li`
  to bit-exact is a candidate follow-up alongside the pow Ziv-retry
  work, not in scope here.
- The asymptotic regimes use optimal (smallest-term) truncation, so
  accuracy is bounded by `≈ e^{−|x|}`; the threshold is placed
  conservatively so the series regime covers everything the
  asymptotic cannot resolve to the requested precision.
