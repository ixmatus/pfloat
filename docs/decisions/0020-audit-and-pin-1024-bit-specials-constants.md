# ADR-0020: Bit-audit and pin the 1024-bit specials constants (2/√π, ln 2π)

- **Status**: accepted
- **Date**: 2026-05-16

## Context

Slices 7b2 and 6m0 established a discipline for hardcoded 1024-bit
constants: each fast-path table is pinned to a three-way bit-exact
agreement between the table, an authoritative high-precision decimal
parsed by the in-repo bit-exact decimal parser, and an independent
in-repo derivation, all equal at p=1024. `LN2_LIMBS_1024` and
`EULER_GAMMA_LIMBS_1024` carry this pin; `PI_LIMBS_1024` was
separately cross-checked correct past 1000 bits.

Two `specials`-tier constants never received the treatment.
`TWO_OVER_SQRT_PI_LIMBS_1024` and `LN_2PI_LIMBS_1024` in
`src/math/mod.rs` had only ad hoc provenance (`mpmath` at slice-4a and
slice-4b authoring time, no regression test). `two_over_sqrt_pi_at`
and `ln_2pi_at` fast-path `prec <= 1024` straight from these tables,
so any encoding error past ~450 bits, the exact failure mode observed
for `ln 2` in slice 7b, would silently corrupt every high-precision
`specials` consumer (erf, erfc, gamma, lgamma, the integral cluster)
and was unverified. The lesson carried from the LN2 defect: a
"runs out of bits" symptom is not self-explanatory; bit-audit the
constant against an independent derivation before trusting it.

## Decision

Audit both tables and make the result a permanent regression guard.

1. Extract `two_over_sqrt_pi_via_table` / `ln_2pi_via_table` helpers in
   `src/math/mod.rs` and have `two_over_sqrt_pi_at` / `ln_2pi_at`
   delegate to them, mirroring `ln_2_via_table` / `euler_gamma_via_table`.
   This is a behaviour-preserving refactor that exposes the raw table
   for direct testing. It is committed separately from any behaviour
   change.
2. Add authoritative ~1115-digit reference decimals
   `TWO_OVER_SQRT_PI_REFERENCE` and `LN_2PI_REFERENCE` to the
   `agm_constants` test module, generated by `mpmath` (Python) at
   `mp.dps = 1130` via `mpmath.mpf(2) / mpmath.sqrt(mpmath.pi)` and
   `mpmath.log(2 * mpmath.pi)`. Reproduction recipe:

   ```
   nix-shell -p "python3.withPackages(ps:[ps.mpmath])" --run \
     "python3 -c 'import mpmath; mpmath.mp.dps=1130; \
       print(mpmath.mpf(2)/mpmath.sqrt(mpmath.pi)); \
       print(mpmath.log(2*mpmath.pi))'"
   ```

3. Add `two_over_sqrt_pi_table_is_correctly_rounded_at_p1024` and
   `ln_2pi_table_is_correctly_rounded_at_p1024`: each asserts
   table == parsed reference == AGM composer at 2048 rounded to 1024,
   bit-exact, the slice 7b2 three-way pin shape.
4. The 2/√π audit failed. The independent AGM path and the
   authoritative decimal agreed bit-for-bit, while the table differed
   in exactly its least-significant limb: slice-4a stored
   `…DCFF6C03`, a truncation, where the correctly-rounded 1024-bit
   value is `…DCFF6C04`. `two_over_sqrt_pi_at` returned a value 1 ULP
   below correctly-rounded for precisions near 1024. Regenerate
   `TWO_OVER_SQRT_PI_LIMBS_1024` to the correctly-rounded value (the
   bit-exact parse of the authoritative decimal, cross-checked against
   the AGM derivation) and correct the misleading "floor(…)" provenance
   comment. The `ln 2π` table passed the audit unchanged.

The fix is a labelled correctness change committed separately from the
behaviour-preserving refactor, per the one-concern-per-commit rule.

## Consequences

- The last two unaudited 1024-bit constants are now pinned three ways.
  Every future edit to the tables, the bit-exact parser, or the AGM
  composers that disturbs the 1024-bit value fails a test. The
  unaudited-constant backlog item is closed; all four 1024-bit
  transcendental constants (π, ln 2, γ, 2/√π, ln 2π) now carry an
  independent-derivation pin.
- A real high-precision correctness defect is fixed: `erf`, `erfc`,
  and the gamma family no longer inherit a 1 ULP error in `2/√π` near
  p=1024. The `differential_erf` and `differential_gamma` MPFR lanes
  pass with the corrected constant (the corrected value moves the
  results toward MPFR, not away).
- The truncation vs round-to-nearest mismatch is recorded so the same
  generation mistake is not repeated for future hardcoded constants:
  store the correctly-rounded value, never the truncated one, and pin
  it.
- Cost: two ~1115-digit string literals in the test module and one
  behaviour-preserving indirection (`*_via_table`) in the hot path
  (the round-to-precision call is unchanged; only the call site moved).
