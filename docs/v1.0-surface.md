# pfloat v1.0 unary surface (frozen)

This document is the authoritative list of unary (`f32 → f32`-shaped
single-real-argument) functions that pfloat v1.0 ships and that the
Phase 1 correctness sweep verifies. The list is frozen at slice
p1.3 per the Phase 1 plan's "Surface freeze" sequencing step. No
trivial aliases are added; ADR-0032 records the rationale for
keeping `cot`, `sec`, `csc`, `cbrt`, `hypot`, `rootn` absent from
Phase 1 and reserving them for direct primary implementations in
the Phase 2 libm shell.

The frozen surface is confirmed against `src/math/` and `src/ops/`
at HEAD; if a function lands in `src/` after this freeze, it joins
the surface for the slice that adds it but does not retroactively
unfreeze the v1.0 list. The Phase 1 plan's "moving surface means
the table never stabilizes" discipline applies.

## Frozen unary surface

### Elementary (21)

```
exp expm1 exp2 exp10
ln log1p log2 log10
sin cos tan
asin acos atan
sinh cosh tanh
asinh acosh atanh
sqrt
```

The exp/log family ships under `feature = "exp-log"`; the trig
family ships under `feature = "trig"`; `sqrt` lives in the base
`big` feature (`src/ops/sqrt.rs`).

### Specials (10)

```
erf erfc
gamma lgamma digamma
zeta
Ei Si Ci li
```

Ships under `feature = "specials"` (with `integrals` for Ei/Si/Ci/li
and `zeta` for zeta).

### Airy (4)

```
Ai Bi Ai_prime Bi_prime
```

In tree as `ai`, `bi`, `ai_prime`, `bi_prime` methods on `BigFloat`
(`src/math/airy.rs`). Ships under `feature = "airy"`.

### Bessel (12 fixed-order entries)

```
J0 J1 Jn(n=2..N)
Y0 Y1 Yn(n=2..N)
I0 I1 In(n=2..N)
K0 K1 Kn(n=2..N)
```

J0, J1, Y0, Y1, I0, I1, K0, K1 are unary per fixed order and
participate in the exhaustive `f32` sweep directly. Jn, Yn, In, Kn
take an integer order `n` as a second argument; the sweep covers a
chosen set of higher orders `n` per family. The N-ladder pinned at
slice p1.35 is `n ∈ {2, 5, 10, 25, 100}` per family — five samples
covering the small-order direct-computation regime (n ≤ 5), the
moderate-order Miller / upward-recurrence regime (n = 10, 25), and
the large-order Debye-asymptotic regime (n = 100). Each (family, N)
row gets its own status TOML (`Jn_2`, `Jn_5`, …, `Kn_100`).
Ships under `feature = "bessel"`.

### Surface size

47 (21 elementary + 10 specials + 4 Airy + 8 Bessel-fixed-order
+ 4 Bessel-with-order-parameter).

## Out of scope at v1.0

### Multi-argument (Phase 1 plan defers)

`pow`, `atan2`, `beta`, `fma`, `agm`. 2^64 input space; cannot be
exhausted over `f32`. These keep their existing differential +
property + worst-case-vector verification posture as their v1.0
rigor. The exhaustive sweep is a future Phase 3+ track.

### Aliases (ADR-0032 defers to Phase 2 libm)

`cot`, `sec`, `csc`, `cbrt`, `hypot`, `rootn`. The original Phase 1
plan proposed adding these as a few-line compositions for surface
parity with libm/MPFR. ADR-0032 rejected that: a correctly rounded
`tan` followed by a correctly rounded reciprocal is not a correctly
rounded `cot` for hard-to-round inputs; the two roundings compose
into up to 1 ULP error in the reciprocal direction. Phase 2 ships
these as direct primary kernels with their own derivations.

### Phase 3+ algorithmic additions

`lambert_w`, `incomplete_gamma`, `incomplete_beta`, `bessel_yn` at
non-integer order, hypergeometric forms. These do not exist in
`src/math/` today and are not part of the v1.0 surface; each gets
swept by the same Phase 1 harness as it lands.

### Internal helpers

The `agm_constants`, `gamma_stirling`, `trig_reduce`, and `ziv`
modules are internal kernels supporting the public surface; they
are not directly verified by the Phase 1 sweep (they are exercised
indirectly through the functions that call them, and pinned by
unit and property tests at their level).

## Post-1.0 additive extensions

The frozen surface grows only by addition under semver. Recorded here
so the authoritative list stays current.

- **1.1 hardware-float conversion** (ADR-0055): `BigFloat::from_f32`,
  `from_f64` (exact widening) and `to_f32_round`, `to_f64_round`,
  `to_f32`, `to_f64` (mode-aware narrowing, returning the IEEE sticky
  flags). Pure Rust, `no_std`, no decimal round trip; the keystone the
  Phase 2 libm shell rounds through, cross-checked bit-exact against
  MPFR in `tests/convert_oracle.rs`. Additive only; no v1.0 signature
  changes.
