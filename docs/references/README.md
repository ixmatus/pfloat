# Reference registry

One file per external source the pfloat family derives from, verifies
against, or names as context: standards, papers, books, web pages, vector
corpora, and oracle software. Each entry carries full provenance
frontmatter (citation, canonical and archived URLs, license, rot risk,
consumers) plus a short prose body. `INDEX.md` is generated by
`scripts/references-index.sh` and holds one line per entry, never content.

This registry is the crate level slice of a cross project convention (the
same schema runs in the sibling repositories); the schema definition of
record for pfloat is ADR-0094. The narrative catalog at
`docs/references.md` stays the function major view (function to source to
module to ADR); this directory is the source major view.

## Schema

Every entry has exactly the frontmatter keys below, in this order. The
literal value `none` marks a field that does not apply; no key is ever
omitted, so the validator checks presence without optionality logic.

| Key | Meaning |
|---|---|
| `slug` | Must equal the filename stem. |
| `category` | `standard`, `paper`, `book`, `web`, `corpus`, or `software`. |
| `citation` | Author, title, venue, year, as a single line. |
| `edition` | Edition, revision, or version pin when one matters. |
| `canonical_url` | The canonical location, or `none` when `document_number` carries it. |
| `document_number` | Standard or report number (`IEEE Std 754-2019`, `N1570`, `MPI-I-98-1-022`). |
| `doi` | DOI when one exists. |
| `archived_url` | Wayback snapshot saved at citation time (or the latest verified existing snapshot when the save endpoint is down; note it in the body and retry). |
| `archive_date` | Date the snapshot was opened and verified, not the snapshot's own timestamp (that lives in the URL). |
| `retrieval_date` | Date the live source was last consulted. |
| `sha256` | Fixity hash; required when `vendor_status` is `vendored` or `derived-subset`. |
| `vendored_path` | Repo path of the vendored or derived artifact. |
| `license` | SPDX identifier or short prose; recorded before any vendoring. |
| `vendor_status` | `vendored`, `pointer-only`, `legally-cannot`, or `derived-subset`. |
| `rot_risk` | `died-once`, `single-maintainer`, `community-run`, `academic-personal`, `stable-publisher`, or `ephemeral`. |
| `provenance_class` | `primary`, `oracle`, `lineage`, or `contextual`. |
| `consumers` | List of repo paths (code, tests, ADRs) that rely on this source. |
| `verification` | One line linking the source to the tests, vectors, or proofs derived from it. |

Body headings, all required: `## Why this source`, `## What it grounds`,
`## Alternatives`. Entries with `category: corpus` additionally require
`## Coverage gaps`; those gap statements feed the reconciliation report at
`coverage-gaps.md`.

## Provenance classes

The class records what the tree actually does with the source, not how
prestigious the source is. Class inflation is the named failure mode of
this registry; when in doubt, choose the weaker class.

- `primary`: an implementation in this repository derives from it.
- `oracle`: a verification lane compares against it; nothing derives from it.
- `lineage`: acknowledged through a direct source (for example a paper
  whose data reaches pfloat through a downstream corpus).
- `contextual`: named for context, as a free proxy for a paywalled
  standard, or to document a gap. `berkeley-testfloat.md` and
  `muller-handbook-fp-2018.md` are the canonical examples: both are
  catalogued precisely because pfloat does not use them, and the entry
  records why.

## Vendor status

`derived-subset` (a pfloat extension to the three value cross project
enum, ADR-0094) marks a source whose data was transcribed or sampled into
a derived in tree artifact without redistributing upstream bytes
verbatim. The entry's `vendored_path` names the derived artifact and
`sha256` pins it; regenerating the artifact is a provenance event, so the
same change must update the hash here.

## Rules

- **Accretion ritual.** When a slice of work cites or relies on a new
  external source, the same slice appends or updates the registry entry
  and saves the canonical URL to the Wayback Machine
  (`https://web.archive.org/save/<url>`). Never defer to a future
  documentation pass.
- **Archive verification.** `archive_date` is recorded only after the
  snapshot has been opened and its content checked by a human or agent.
  The save endpoint returns success for captcha pages and redirect stubs;
  an unverified snapshot is rot insurance that silently lapsed. Re-verify
  rot prone snapshots (any `rot_risk` other than `stable-publisher`)
  roughly annually.
- **Fix forward.** When a module rename breaks a `consumers` path, update
  the path. Never delete the consumer line to silence the validator; the
  consumers list is what makes an entry auditable.
- **Copy contract.** Downstream synthesis repositories copy entries
  verbatim rather than linking here. An importer must rewrite `consumers`
  and `verification` for its own tree and keep every other field
  unchanged.
- **Paywalled standards** are pointer only: cite clause numbers and name
  the free proxy literature in the body. When in doubt about any
  vendoring question: pointer plus archive, not a copy.

## Adding an entry

1. Copy `TEMPLATE.md` to `<slug>.md`; fill every key.
2. Save the canonical URL to the Wayback Machine; open the snapshot and
   verify it before recording `archived_url` and `archive_date`.
3. Regenerate the index: `./scripts/references-index.sh --emit > docs/references/INDEX.md`.
4. Check: `./scripts/references-index.sh --check` (CI runs this per push).
