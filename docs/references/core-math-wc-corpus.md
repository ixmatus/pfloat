# CORE-MATH worst case rounding corpus

## Why this source

The maintained machine readable form of the hard to round literature:
per function `.wc` files curating Lefevre's worst case database,
annotated with BaCSeL search parameters and a minimum identical bits
guarantee per block. These are the inputs where a correctly rounded
implementation is most likely to be wrong, which makes them the highest
value finite test set that exists for this surface.

## What it grounds

The hard to round differential lane. The vendor status is
`derived-subset` (the value this corpus motivated, ADR-0094): inputs
are transcribed (roughly fifty representative cases per function,
twenty four functions), outputs are NOT transcribed but independently
recomputed via mpmath at 200 bits and rounded to binary64 NearestEven,
and the upstream `.wc` files are not vendored. The derived artifact is
`tests/differential/lefevre_muller_data.rs` (generated by
`scripts/extract_lefevre_muller.py`; the sha256 above pins it, so
regenerating the corpus updates this entry in the same change).
pfloat-libm carries its own derived table at
`pfloat-libm/tests/harness/lefevre_muller_data.rs`.

License compliance: the MIT permission notice is reproduced verbatim in
the test file headers, the principal copyright holders are named, and
the full posture lives in `docs/lefevre-muller-corpus-provenance.md`
(the narrative document this entry summarizes; the registry entry is
the schema shaped record, the provenance document is the depth).

## Coverage gaps

These gaps are what the README disclosures' "inputs no test happened to
cover" clause is made of; see `coverage-gaps.md`.

- binary64 only: no hard to round vectors exist for the arbitrary
  precision surface itself (see `berkeley-testfloat.md` for why none
  can).
- Unary only as shipped: CORE-MATH's `atan2` and `pow` data is
  deliberately not sampled (multi argument deferred), and `cbrt`,
  `hypot`, `rootn` have no corpus analog in the sampled set.
- Sampled, not exhaustive: roughly fifty cases per function from files
  on the order of 100 MB; the unsampled tail is unexercised.
- Function aliasing: pfloat's `ln` maps to CORE-MATH `log`, `gamma` to
  `tgamma`; the special functions beyond the gamma family (Bessel,
  Airy, zeta, integrals) have no CORE-MATH analog at all.
- The exp head block excluded at slice 8b (saturating region) remains
  excluded.

## Alternatives

Transcribing outputs from the Muller et al Handbook tables was rejected
(print transcription risk, narrower coverage); recomputing outputs
independently also turns the corpus into a cross check of mpmath
against pfloat rather than a copy of upstream claims.
