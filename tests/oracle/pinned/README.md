# Pinned worker-output corpus (ADR-0035 Tier 5)

This directory holds the durable contract on the Arb oracle's
worker output for a curated set of `(FnId, input_bits, mode)`
triples. Each entry pins the certified `f32` bit pattern the
worker produced at the time of the pin, plus a short provenance
note explaining how the entry was derived.

## Why pin worker output

ADR-0035 lays out the verification stack:

- Tier 1: property tests on `certified_round_f32` (the shared
  rational-rounding routine), exhaustive over f32 boundary
  classes.
- Tier 2: mpmath cross-check that agrees with Arb on every
  sampled input.
- Tier 3: hand-derived tricky-case corpus the property tests
  reference.
- Tier 5 (this file): pinned worker output diff-checked per push.
- Tier 6 (slice p1.10+): Maxima sampling layer for three-way
  agreement on the hard cases.

The pin is the durable contract: any change to the Arb worker, to
the shared rounding routine, or to the FLINT/Arb dependency
version must explain any output change as either a fix or a
regression. The pin file is the artifact that makes "explain the
change" possible.

## File layout

One TOML file per FnId (with parametric Bessel orders folded into
a single file per family). Each file contains a `[[entry]]` table
array; each entry has:

```toml
input_bits = "0x00000001"      # f32 bit pattern, lowercase hex
mode = "NE"                    # IEEE 754 rounding mode
certified_bits = "0x00000001"  # the f32 the worker produced
provenance = "..."             # short note on how the entry was derived
```

The `provenance` field documents WHY this particular entry was
pinned. Initial entries are:

- **hand-derived from first principles**: a closed-form analysis
  established the certified `f32` independently of any worker.
  Examples: `I1(2^-149) = 2^-150 + 2^-451` (NE rounds to mantissa
  1 because truth is sub-midpoint-correction above the midpoint
  between mantissas 0 and 1); `Ci(+0) = -inf`; `K_n(+0) = +inf`;
  exact-zero results for `li`, `si`, `i1` at `+0`.
- **two-oracle agreement**: Arb and mpmath workers both certify
  the same f32; the value is pinned with that source.
- **maxima triple-check** (slice p1.10 follow-up): all three
  oracles (Arb + mpmath + Maxima) agree.

## How to regenerate

The pin files are regenerated by the slice-close ritual when an
oracle change lands. The regeneration script (planned at slice
p1.10) compares the new worker output against the pinned values
and produces a diff that the slice author reviews; a fix-forward
or revert decision lives in the slice's commit message and the
ADR-0035 cross-reference.

The per-push gate `tests/oracle_pinned_corpus.rs` reads every
TOML file in this directory and asserts the live Arb worker
matches every entry. A push that changes worker output without
updating the pin fails the gate with a diagnostic listing the
diverged entries.

## What is NOT pinned

- The full f32 sweep (65536 inputs per function): too large; the
  status table in `tests/oracle/status/` records the aggregate
  per-row outcome instead.
- mpmath / Maxima output directly: the pin captures the Arb
  worker's output, because Arb is the primary oracle. The other
  oracles are cross-checks that run alongside the per-slice
  re-sweep. A divergence between the live Arb worker and the
  pinned values halts; a divergence between Arb and another
  oracle halts the regeneration step (and triggers investigation
  before any pin update).
